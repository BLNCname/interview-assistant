# Если OpenRouter не проходит проверку

В версии 0.1.3 разные ошибки скрывались за сообщением `OpenRouterError: readiness probe failed`. Оно не позволяет установить, отсутствует ли ключ, отклонил ли его сервер или недоступно соединение. В 0.1.4 эти причины отображаются отдельно. Обновите приложение через [последний Setup.exe](https://github.com/BLNCname/interview-assistant/releases/latest) и повторите Run checks.

## Порядок настройки

1. Откройте **Settings → Models** и сначала выберите **OpenRouter (cloud)**. При переключении провайдера несохранённое поле ключа очищается, чтобы не отправить ключ другого сервиса.
2. Вставьте в **API key / token** сам ключ OpenRouter, без кавычек и слова `Bearer`. Нужен ключ для выполнения запросов, а не management/provisioning key.
3. Укажите точный **Text model**. Для проверки ключа модель не используется; для проверки генерации она нужна. **Vision model** можно оставить пустым, если скриншоты не используются.
4. Нажмите **Run checks**: эта кнопка сначала сохраняет настройки и ключ, затем пересоздаёт клиент и запускает проверки. Отдельное нажатие Save допустимо, но не обязательно.

После сохранения поле ключа очищается в интерфейсе — это штатное поведение. Сохранённый ключ остаётся в Windows Credential Manager. В 0.1.4 стартовое уведомление о ненайденной/повреждённой конфигурации исчезает после успешного сохранения; в 0.1.3 оно могло оставаться и вводить в заблуждение.

## Как читать Diagnostics

| Фрагмент сообщения | Значение и следующий шаг |
|---|---|
| `API key is not configured` | Приложение не получило ключ; сетевого запроса с ним не было. Выберите OpenRouter и вставьте ключ после переключения провайдера |
| `rejected the API key` | Запрос отклонён с кодом авторизации. Проверьте, что ключ активен, целиком скопирован и принадлежит OpenRouter |
| `denied access` | Доступ запрещён. Проверьте разрешения и тип ключа, доступ аккаунта и ограничения выбранной модели |
| `insufficient credits` | Для запроса не хватает кредитов либо достигнут лимит расходов ключа. Проверяйте также выбранную модель |
| `rate limit` | Достигнут лимит запросов. Подождите перед повторной проверкой |
| `connection failed` / `timed out` | Не удалось установить или завершить соединение с API. Проверьте сеть, DNS, TLS и доступ из приложения |
| `endpoint or model is unavailable` | Адрес API или модель недоступны. Если упала строка проверки ключа, изменение модели не исправляет проверку ключа |
| `unexpected response` | Ответ не соответствует ожидаемому формату API. Проверьте доступность сервиса и сетевые посредники |

Если проверка ключа и `model_discovery` имеют статус `ready`, а `model_load_warmup` и `streaming_ttft` завершаются с `RuntimeError`, ключ принят и каталог моделей получен: сбой возник на этапе генерации. В версии 0.1.3 такой общий текст не раскрывает причину. Обновите приложение до 0.1.4 и повторите **Run checks**, чтобы получить уточнённое сообщение. По одному `RuntimeError` нельзя заключить, что ключ неверен или требуется пополнение баланса.

**Подтверждённый случай — 9 сентября 2026 года.** Для `thinkingmachines/inkling-small:free` проверка ключа вернула HTTP 200, модель присутствовала в каталоге, но запрос генерации получил HTTP 403. Ответ API указал ограничение этого бесплатного варианта: использование только через агентные приложения (`agentic harnesses`). Оно также приведено в [официальной карточке модели](https://openrouter.ai/thinkingmachines/inkling-small:free). Учёт `usage` до и после отказа оставался равным 0. Действительный ключ и наличие модели в каталоге не гарантируют доступ к её конкретному бесплатному варианту; в этом случае выберите другую доступную модель.

**Проверенный текстовый вариант — 9 сентября 2026 года.** В **Settings → Models** укажите **Text model** = [`cohere/north-mini-code:free`](https://openrouter.ai/cohere/north-mini-code:free), оставьте **Vision model** пустым и нажмите **Run checks**. Модель принимает только текст, поэтому для скриншотов она не подходит. Через рабочий клиент приложения все четыре проверки OpenRouter получили `ready`: ключ, каталог моделей, прогрев и потоковый ответ. Прогрев вернул `OK` с первым фрагментом через 583,3 мс; русский ответ с системным промптом приложения начал поступать через 2 424,96 мс и завершился за 3 262,34 мс. Для обоих успешных запросов API сообщил `cost=0`; учёт расходов аккаунта `usage` до и после оставался равным 0. Доступность и квоты могут отличаться для другого аккаунта или в другое время.

В дополнительных проверках вариант Google Gemma вернул HTTP 429, а передача собственных заголовков атрибуции приложения не сняла HTTP 403 для Inkling Small Free.

Для бесплатной проверки общей доступности откройте [каталог API OpenRouter](https://openrouter.ai/api/v1/models) в браузере: ожидается JSON. Этот публичный каталог доступен без ключа, поэтому его открытие **не подтверждает действительность ключа**. Браузер и приложение могут использовать разные настройки сети.

Сам ключ проверяется отдельным [официальным GET /api/v1/key](https://openrouter.ai/docs/api/api-reference/api-keys/get-current-api-key), без генерации текста. Проверки прогрева модели и первого ответа выполняют запрос генерации и могут расходовать квоту выбранной модели.

Если проверка всё ещё не проходит, передайте автору **название строки и полный текст Message** из Diagnostics; текст доступен также во всплывающей подсказке. Ключ, Authorization-заголовок и содержимое Windows Credential Manager передавать не нужно. Конкретную причину на другом компьютере нельзя установить только по общей ошибке старой версии.
