# Interview Assistant — восстановление после переноса на Windows

Дата: 16 июля 2026 г.
Статус: визуальное направление утверждено; ожидается проверка письменной спецификации.

## 1. Цель

Привести перенесённый учебный проект к воспроизводимому рабочему состоянию на текущем ПК с NVIDIA RTX 5070 Ti:

- восстановить корректную структуру Git/worktree без потери существующей истории;
- установить совместимый CUDA 12 runtime и cuDNN 8 для GPU-распознавания речи;
- заменить несовместимую прозрачность верхнего окна Liquid Ribbon на механизм, при котором Windows принимает `WDA_EXCLUDEFROMCAPTURE`;
- изменить основной цвет Ribbon с голубовато-синего на нейтральный графитовый;
- подтвердить результат автоматическими тестами и реальными Windows-пробами.

Работа не расширяет функциональность учебного приложения и не меняет его заявленные границы использования.

## 2. Установленные причины

### Git/worktree

Завершённая версия проекта находится в `.worktrees/feature-interview-assistant` на ветке `feature/interview-assistant`, но оба служебных указателя worktree сохранили абсолютный путь с предыдущего компьютера. Из-за этого Git помечал worktree как `prunable`. В репозитории также есть повреждённая служебная ссылка Codex и сгенерированные `src/*.egg-info`/кэши, не являющиеся исходным кодом.

### CUDA STT

Драйвер RTX 5070 Ti исправен, но в системе доступны CUDA Toolkit 13.x. Установленный CTranslate2 4.8.1 ожидает CUDA 12.x, а для speech recognition — cuDNN 8. Реальная загрузка Whisper доходит до GPU и завершается ошибкой отсутствующего `cublas64_12.dll`.

### Capture affinity

`SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` успешно применяется к обычному top-level окну, к окну с `setWindowOpacity(0.88)` и к окну со скруглённой маской. Он возвращает Win32 error 8, когда top-level `LiquidRibbon` использует `WA_TranslucentBackground`. Следовательно, несовместимость вызвана не прозрачностью вообще, а layered/translucent режимом Qt верхнего окна.

## 3. Выбранное решение

### 3.1. Финальная структура Git

1. Исправить двусторонние указатели linked worktree на текущие абсолютные пути.
2. Работать и тестировать на существующей ветке `feature/interview-assistant`, сохраняя ветку `main` и её историю без переписывания.
3. Проверить повреждённую служебную ссылку Codex и удалить только её, если целевой объект действительно отсутствует. Пользовательские ветки и теги не затрагивать.
4. Удалить только генерируемые кэши и `src/interview_assistant.egg-info`; добавить их в ignore/явно ограничить package discovery, если это требуется для воспроизводимой editable-установки.
5. После прохождения проверок сделать завершённую ветку обычным корневым checkout проекта и убрать ставшую ненужной скрытую регистрацию linked worktree. Физические файлы удалять только после подтверждения, что нужные коммиты доступны из корня.

Итог: пользователь открывает завершённый проект в текущем workspace без зависимости от старого пользовательского пути и без скрытой второй рабочей копии.

### 3.2. CUDA 12 и cuDNN 8

- Установить официальный CUDA 12.x runtime/toolkit параллельно с существующим CUDA 13.x.
- Не устанавливать и не откатывать display driver из CUDA-пакета: текущий драйвер новее и поддерживает CUDA 12 runtime.
- Установить cuDNN 8.9.7 для CUDA 12.x. cuDNN 9 не использовать, поскольку текущая версия CTranslate2 документированно требует cuDNN 8 для speech recognition.
- Добавить в приложение раннюю Windows-настройку DLL search path: сначала найденные каталоги CUDA 12 и cuDNN 8, затем штатный поиск Windows. Это делает запуск из `.venv` и packaged EXE независимым от порядка глобального `PATH` и не ломает CUDA 13 для других программ.
- При отсутствии библиотек диагностика должна перечислять недостающие DLL и проверенные каталоги, а не завершаться только низкоуровневым исключением CTranslate2.
- Установка может вызвать стандартный UAC-запрос Windows. Секрет LM Studio в команды, логи и конфигурационные файлы не передаётся.

Опорные требования: [CTranslate2 installation](https://opennmt.net/CTranslate2/installation.html) и [NVIDIA cuDNN archive](https://developer.nvidia.com/rdp/cudnn-archive).

### 3.3. Capture-compatible Liquid Ribbon

Верхнее окно `LiquidRibbon`:

- больше не устанавливает `WA_TranslucentBackground`;
- получает `setWindowOpacity(0.88)` по умолчанию;
- сохраняет совместимость со старыми конфигами: эффективная прозрачность окна ограничивается безопасным диапазоном `0.65..1.0`, но загрузка старого значения не ломается;
- получает скруглённую оконную маску радиусом 18 px, пересчитываемую при resize и смене collapsed/expanded состояния;
- применяет и затем проверяет `WDA_EXCLUDEFROMCAPTURE` только после создания HWND, как и раньше;
- сохраняет drag, collapse/expand, streaming, hotkeys и текущую геометрию.

Дочерние виджеты могут рисовать собственные полупрозрачные цвета, если это не переводит top-level HWND обратно в несовместимый режим.

### 3.4. Графитовая палитра

Утверждённый внешний вид:

- основной градиент: `#34363A` → `#25262A`;
- внутренние поверхности: нейтральный тёмный графит без синего оттенка;
- основной текст: близкий к белому;
- вторичный текст: нейтральный серый с достаточным контрастом;
- тонкая граница и разделители: светло-серые с небольшой альфой;
- небольшой cyan/teal акцент допускается только для функциональных состояний — курсора streaming, статуса модели или активного элемента;
- высота свёрнутого Ribbon остаётся 48 px, радиус внешнего контура — 18 px.

Стиль должен оставаться читаемым как поверх светлого, так и поверх тёмного окна. Графитовый фон не должен выглядеть синим при стандартном профиле sRGB.

## 4. Тестовая стратегия

Изменения выполняются через failing test → минимальная реализация → полный regression run.

### Git и упаковка

- `git worktree list --porcelain` содержит только существующие пути;
- `git fsck`/проверка refs не сообщает о повреждённой перенесённой ссылке;
- editable install импортирует пакет из корневого `interview_assistant`, а не из случайно созданного `src`;
- packaging smoke test и запуск diagnostics из EXE проходят из короткого TEMP-пути.

### CUDA

- unit-тесты покрывают выбор CUDA 12/cuDNN 8 и сообщения об отсутствующих DLL;
- `cublas64_12.dll`, cuDNN DLL и `ctranslate2.get_cuda_device_count()` доступны в новом процессе;
- faster-whisper реально загружает модель на `device=cuda` и обрабатывает короткий тестовый аудиофрагмент;
- после проверки модель выгружается, временные файлы удаляются.

### Ribbon и capture affinity

- unit-тест подтверждает отсутствие `WA_TranslucentBackground` у top-level Ribbon;
- effective window opacity и скруглённая маска проверяются отдельно;
- существующие UI/state-machine тесты остаются зелёными;
- реальная Win32-проба создаёт Ribbon, применяет `WDA_EXCLUDEFROMCAPTURE`, читает значение обратно и ожидает `0x11`;
- GUI smoke test держит приложение активным минимум 15 секунд без необработанного исключения.

## 5. Критерии приёмки

Работа считается завершённой, когда одновременно выполнены условия:

1. Корень репозитория содержит завершённую ветку проекта и не ссылается на старый компьютер.
2. Полный набор тестов проходит; отдельно задокументировано только внешнее ограничение PowerShell/длины пути, если оно всё ещё воспроизводится.
3. Реальный CUDA STT запуск на RTX 5070 Ti успешно распознаёт тестовый звук.
4. Реальный Ribbon получает и подтверждает `WDA_EXCLUDEFROMCAPTURE`.
5. Ribbon визуально соответствует утверждённому графитовому варианту с opacity 0.88.
6. LM Studio token остаётся только в Windows Credential Manager (`InterviewAssistant` / `lmstudio_api_token`) и не появляется в Git diff или логах.

## 6. Откат и риски

- CUDA 12 ставится side-by-side, поэтому удаление его компонентов не затрагивает CUDA 13 и display driver.
- До финального переключения корня сохраняются обе рабочие копии и обе ветки.
- Перед удалением любой worktree выполняются проверки commit SHA и clean status.
- Изменение прозрачности может слегка отличаться визуально от per-pixel alpha на разных темах Windows; это компенсируется графитовой заливкой и оконной маской.
- `WDA_EXCLUDEFROMCAPTURE` остаётся best-effort функцией Windows, а не защитой от всех способов съёмки экрана.
