# Сетевой установщик 0.1.3

Для установки Interview Assistant скачайте один **`Setup.exe`** из [GitHub Releases](https://github.com/BLNCname/interview-assistant/releases/latest). Он содержит ядро приложения и базовый Python. Во время установки мастер получает закреплённые версии публичных библиотек и STT-модели, проверяет файлы и размещает их рядом с приложением. Git, отдельный Python, Node.js и CUDA Toolkit на компьютере пользователя не нужны. Настройка после установки описана в [README](../README.md).

## Что загружается

| Часть | Источник | Размер выпуска 0.1.3 |
|---|---|---:|
| Setup с кодом приложения и базовым Python | Приватный GitHub Release, загрузка через браузер | 38 089 141 байт (38,09 МБ) |
| 35 закреплённых wheel-архивов библиотек, включая Qt и CUDA/cuDNN | PyPI, `files.pythonhosted.org` | 1 465 431 713 байт |
| `large-v3-turbo` и сопутствующие файлы модели | Hugging Face, закреплённая ревизия | 1 621 667 428 байт |

Размеры измерены по собранному установщику и проверенному manifest. ГБ здесь — десятичные; Windows может показывать другие числа. При пустом кеше загружается **3 087 099 141 байт (3,09 ГБ)** в дополнение к самому Setup и служебному сетевому трафику. Установленное приложение занимает около **4 ГБ**, сохранённый кеш — около **3,1 ГБ**. С учётом распаковки и временных копий рекомендуется **12 ГБ свободного места**. Это запас для установки, а не измеренный пик; локальные модели LM Studio требуют дополнительного места.

Список URL, размеров и SHA-256 фиксируется при сборке. Версии библиотек берутся из [`uv.lock`](../uv.lock), файлы STT — из [`stt_model_manifest.json`](../packaging/stt_model_manifest.json). Setup не выбирает новые версии зависимостей при каждом запуске. Переход на новый состав выполняется новым выпуском установщика.

Модель закреплена на ревизии `0a363e9161cbc7ed1431c9597a8ceaf0c4f78fcf` репозитория [dropbox-dash/faster-whisper-large-v3-turbo](https://huggingface.co/dropbox-dash/faster-whisper-large-v3-turbo/tree/0a363e9161cbc7ed1431c9597a8ceaf0c4f78fcf). Драйвер NVIDIA, LM Studio и модель для генерации ответов в эти загрузки не входят. Требования к GPU и режим CPU приведены в [HARDWARE_RU.md](HARDWARE_RU.md).

## Почему код приложения находится внутри Setup

Репозиторий остаётся приватным. GitHub требует авторизацию для доступа к файлам закрытого релиза; анонимное получение release asset доступно для публичных ресурсов. Это ограничение описано в [GitHub REST API для release assets](https://docs.github.com/en/rest/releases/assets#get-a-release-asset).

Поэтому доступ к GitHub используется только в браузере, когда пользователь получает `Setup.exe`. Собранный код приложения уже находится внутри него. Мастер не содержит персональный PAT издателя и не требует GitHub OAuth, логина или доступа к исходникам во время установки. Он обращается к публичным источникам библиотек и модели. Сам репозиторий для этого открывать не требуется.

Приложение собирается PyInstaller: в поставку включается интерпретатор, поэтому установленный в системе Python не требуется. Это соответствует [модели распространения PyInstaller](https://pyinstaller.org/en/stable/operating-mode.html). При подготовке сетевого Setup часть файлов полной сборки переносится в список загрузок; после установки восстанавливается нужная приложению структура каталогов.

## Проверка загрузок и повторный запуск

Перед запуском сверяйте SHA-256 самого `Setup.exe` со значением в описании релиза:

```powershell
Get-FileHash -LiteralPath .\Setup.exe -Algorithm SHA256
```

Мастер получает зависимости по HTTPS и проверяет размер и SHA-256 каждого загруженного артефакта. Для файлов, извлечённых из wheel-архивов и выбранных для установки, также проверяются закреплённые контрольные суммы. Несовпадение останавливает подготовку, а не разрешает использовать неизвестный файл.

При обновлении с 0.1.1 мастер удаляет 16 конкретных устаревших DLL из корня `_internal`, которые отсутствуют в новой сборке. Это выполняется только после успешной загрузки, распаковки и проверки всех компонентов. Остальные файлы этого каталога не удаляются целиком; при ошибке или отмене на этапе подготовки старые DLL сохраняются.

Полностью загруженные файлы сохраняются в:

```text
%LOCALAPPDATA%\InterviewAssistant\InstallerCache
```

При повторном запуске целые файлы используются только после проверки. **Побайтовой докачки нет:** если передача конкретного файла прервалась, этот файл загружается заново с начала. Остальные целые файлы в кеше повторно скачивать не нужно. Кеш сохраняется после завершения или отмены мастера; после закрытия Setup его можно удалить вручную, если повторная установка не нужна.

Если появляется ошибка загрузки, проверьте соединение, доступность источников и свободное место, затем повторите запуск того же Setup. При повторном несовпадении контрольной суммы передайте автору релиза текст ошибки. Не заменяйте файлы произвольными версиями и не обходите проверку.

Установщик использует штатные средства Inno Setup 6.7.2. В частности, [`DownloadTemporaryFile`](https://jrsoftware.org/ishelp/topic_isxfunc_downloadtemporaryfile.htm) поддерживает HTTPS, прогресс и проверку заданного SHA-256. Постоянный кеш и проверка выбранных файлов — логика этого проекта поверх механизма загрузки Inno.

## Установка и ограничения

Установка выполняется для текущего пользователя, по умолчанию в `%LOCALAPPDATA%\Programs\InterviewAssistant`. Библиотеки размещаются внутри приложения; мастер не устанавливает глобальный Python или CUDA Toolkit. После завершения в меню «Пуск» появляется Interview Assistant. Все ключи провайдеров и MCP вводятся в Settings, а не в Setup.

Страница `Speech recognition hardware` показывает обнаруженную NVIDIA и рекомендуемый начальный режим. Примените рекомендацию после установки в **Settings → Audio**: CUDA + Int8/Float16 либо CPU + Int8. Это подсказка по оборудованию, а не измерение скорости; существующая конфигурация приложения автоматически не переключается.

Учебный `Setup.exe` не подписан сертификатом издателя. Проверка SHA-256 подтверждает совпадение с опубликованным файлом, но не заменяет подпись издателя. Полный транзакционный откат всех изменений при любом сбое не гарантируется. При ошибке не считайте установку законченной: устраните причину и повторите её.

Разделение небольшого установщика и загружаемых компонентов — обычный подход для Windows. Например, [WiX Burn позволяет сочетать встроенные и скачиваемые пакеты](https://docs.firegiant.com/wix/schema/wxs/exepackage/). Этот проект использует Inno Setup; свойства кеша или отката WiX на него автоматически не распространяются.

## Сборка издателем

Основной сценарий — [`scripts/build_online_installer.ps1`](../scripts/build_online_installer.ps1). Сначала создаётся и проверяется полная portable-сборка PyInstaller, затем по её описи и `COLLECT-00.toc` строится manifest загрузок. Скрипт проверяет публичные архивы и соответствие выбранных файлов portable-сборке до компиляции Setup.

Команда и подготовка окружения приведены в [BUILD_RU.md](BUILD_RU.md). Для версии 0.1.3 используется `Compression=none`; результат для публикации — один `Setup.exe`. Manifest, журналы сборки и файл с контрольной суммой остаются у издателя; SHA-256 Setup указывается в описании релиза. Проверки установки, удаления, работы с пустым и заполненным кешем оформляются отдельно в [отчётах испытаний](validation/).
