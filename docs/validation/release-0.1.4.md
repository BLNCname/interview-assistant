# Проверка выпуска 0.1.4

Проверено 9 сентября 2026 года на Windows x64. [Релиз](https://github.com/BLNCname/interview-assistant/releases/tag/v0.1.4).

## Исправления и границы результата

В 0.1.3 диагностика скрывала причины отказа OpenRouter за `OpenRouterError: readiness probe failed`; при прогреве модели исходная ошибка дополнительно превращалась в общий `RuntimeError`. В 0.1.4 сохраняется тип ошибки провайдера, а Diagnostics показывает заранее заданное описание причины: отсутствие ключа, отказ авторизации, нехватка кредитов, лимит запросов, ошибка соединения, недоступность сервиса или некорректный запрос. Произвольный текст исключения, ключи и заголовки в таблицу не выводятся.

Отсутствующий локальный ключ теперь отличается от HTTP 401, полученного от сервера. Стартовое сообщение об отсутствующей или повреждённой конфигурации исчезает после успешного сохранения. Сохранение ключа кнопкой Run checks уже работало; новые GUI-тесты подтверждают, что настройки сохраняются до создания клиента и клиент получает новый ключ.

Первый скриншот с компьютера преподавателя не позволял определить причину отказа. На следующем скриншоте ключ уже принят и модель найдена, но проверки генерации завершаются общим RuntimeError. Позже пользователь предоставил тестовый ключ и модель Inkling Small Free: живой запрос воспроизвёл отказ доступа к этому бесплатному варианту. Другая бесплатная модель Cohere успешно прошла все четыре проверки провайдера и ответила на вопрос интервью. Работа реального запроса на компьютере преподавателя после обновления пока не подтверждена. [Инструкция по диагностике](../OPENROUTER_TROUBLESHOOTING_RU.md).

Пять пропусков: три теста symlink требуют недоступной привилегии Windows, два относятся к POSIX. Все четыре команды финальной проверки выполнены на одном наборе из 154 файлов; изменений этих файлов во время проверок не было. Qt и Inno запускались на отдельном рабочем столе.

Регрессионные тесты воспроизводят HTTP 401/402/403/404/429/503 через настоящий клиент с подменой транспорта, сетевую ошибку, отсутствие ключа до сетевого запроса, передачу ошибки прогрева в Diagnostics и сохранение конфигурации через GUI. Неизвестные и поддельные коды ошибок также проверены на отсутствие вывода исходного текста. Тест передачи HTTP 402 проходит через OpenRouterClient, `_warm_model` и ReadinessRunner.

Первый полный прогон обнаружил, что новый импорт клиента загружал HTTP-библиотеки в быстрой офлайн-проверке. Импорт перенесён на этап выполнения readiness. После исправления полный прогон повторён; приведённые выше результаты относятся к окончательной версии. Самопроверка собранного EXE также выполнена отдельно.

## Артефакты и воспроизводимость состава

| Артефакт | Размер, байт | SHA-256 |
|---|---:|---|
| `Setup.exe` | 38 090 362 | `f9536aeb374de226e900a8adcefc4c8724d321fc1f9a9c4d1969fe4fdd1547c2` |
| `InterviewAssistant.exe` | 14 315 480 | `29ef09fed18f77954d58557666045baa2a5bd48a384b9f3feed4c59d406873a7` |

Установщик Inno Setup 6.7.2 использует `Compression=none`. Для пользователя публикуется один Setup.exe. Полный состав: **4161 файл, 4 017 443 763 байта**; 103 файла на 34 915 929 байт встроены в Setup, остальные 4058 восстанавливаются из закреплённых публичных артефактов. 35 wheel-архивов и 6 файлов STT требуют **3 087 099 141 байт** загрузки при пустом кеше. Зависимости относительно 0.1.3 не обновлялись.

После полной сборки окончательный EXE пересобран с неизменными стадиями Analysis/PYZ/EXE исходного spec. Чтобы не создавать дополнительную копию четырёхгигабайтного каталога, сохранены 4160 внешних файлов первой сборки. Сопоставление путей и типов обоих Analysis показало одинаковый состав: 4159 файлов побайтово идентичны; у `base_library.zip` отличаются порядок записей и общий хеш архива, но все 155 членов, их содержимое и метаданные совпадают. Сохранён исходный архив. Сравнение полной описи до и после замены EXE подтвердило, что изменился только `InterviewAssistant.exe`.

Окончательный состав сверён по всем размерам и SHA-256; встроенные code objects сравнивались с текущими исходниками без исполнения, с нормализацией только co_filename. Входы сборки установщика хешировались до и после компиляции.

## Настоящая установка

Окончательный Setup установлен в отдельную тестовую папку из заполненного пользовательского кеша. По журналу Inno установка заняла **168,817 с**, получила **41 попадание в проверенный кеш** и завершилась с кодом 0. После установки сверены все 4161 файл и хеши модели; frozen diagnostics завершилась с кодом 0, `status=ok`, `frozen=true`, CUDA device count 1, недостающих runtime DLL нет.

Повторная установка остановилась на предварительной проверке диска: требовалось 6348 MiB, доступно 5113 MiB. От запуска до закрытия — **23,342 с**. Успешное обновление именно этого выпуска не заявляется. Позже повторно сверены все 4161 файл установленной версии и все 16 добавленных тестовых старых DLL: отказ до начала установки сохранил их без изменений. Успешное обновление с очисткой старых DLL проверялось в [выпуске 0.1.3](release-0.1.3.md); соответствующий код установщика в 0.1.4 не изменён.

После полной проверки удалены только 16 файлов с точным тестовым содержимым `old-release-fixture`, затем запущен штатный деинсталлятор тестовой копии. Удаление заняло **2,364 с**, exit code 0; папка установки и её регистрация AppId удалены. Подготовительная повторная сверка заняла 92,753 с, весь сценарий завершения — 98,843 с с учётом запуска отдельного рабочего стола. Установка и удаление запускались в обычном пользовательском контексте на отдельных рабочих столах, которые не активировались. Пользовательская конфигурация и ключи не использовались.

## Секреты и ограничения проверки

В окончательной поставке проверены 377 текстовых файлов и Python-архивы EXE/PYZ/base_library: 43 682 code objects, 363 619 строковых констант. Настоящие значения четырёх известных приложению типов ключей сравнивались только в памяти; значения не выводились. Найденных ключей и ошибок сканирования нет. Модель, нативные DLL/PYD и изображения этим поиском строк не покрываются; происхождение зависимостей проверяется закреплёнными хешами.

После офлайн-проверок пользователь предоставил тестовый ключ для живого теста. Ключ передавался процессам через stdin; он не добавлялся в конфигурацию, Credential Manager или исходники. В отчётах сохранены только результаты запросов и выбранные числовые поля учёта. Firecrawl в этом прогоне не вызывался.

## Живой OpenRouter

Проверено 9 сентября 2026 года через текущие `OpenRouterClient`, `OpenRouterRegistry`, `ProductionReadinessProbes`, `_warm_model` и `ReadinessRunner`. Выполнялись четыре проверки провайдера; аппаратные проверки в этот сценарий не входили. Параметры соответствуют приложению: `max_tokens=1200`, `temperature=0.55`, потоковый Chat Completions. Проверки прогрева и TTFT используют один общий запрос генерации.

| Модель | Результат |
|---|---|
| `thinkingmachines/inkling-small:free` | `/key` и каталог HTTP 200, генерация HTTP 403. Ответ сервиса указывает доступ только через agentic harnesses. Запрос с настоящими названием Interview Assistant и URL проекта в официальных заголовках attribution также отклонён с той же причиной |
| `google/gemma-4-26b-a4b-it:free` | Ключ и каталог приняты; генерация HTTP 429 от Google AI Studio. Успешная генерация не подтверждена |
| `cohere/north-mini-code:free` | Все четыре проверки провайдера ready; прогрев и ответ на вопрос интервью успешно завершены с `finish_reason=stop` |

Ограничение Inkling описано и в [официальной карточке](https://openrouter.ai/thinkingmachines/inkling-small:free). Добавление собственных [заголовков attribution](https://openrouter.ai/docs/app-attribution) идентифицирует приложение, но в выполненном тесте не предоставило доступ к этой модели. Аутентификация ключа работала во всех трёх случаях.

Для Cohere прогрев вернул `OK`: первый текст **583,30 мс**, завершение **585,88 мс**. Затем с системным промптом приложения задан русский вопрос о различии аутентификации и авторизации. Первый текст пришёл через **2424,96 мс**, ответ завершён через **3262,34 мс**; получено 108 текстовых фрагментов без ошибок.

По данным `usage` прогрев использовал 7 входных и 30 выходных токенов, ответ — 1172 входных и 269 выходных. Сервис сообщил `cost=0` для обеих генераций; числовой расход ключа до и после остался 0. Эти значения — учёт провайдера, а не локальная оценка токенизатором. Первая отдельная попытка контрольного запуска остановилась на дополнительном запросе состояния ключа до генерации; следующая попытка сохранила полный результат. Условия бесплатных моделей и их доступность могут измениться.

Контрольный вариант Cohere принимает только текст: его нельзя использовать как Vision model для скриншотов. Живой тест выполнялся из исходников теми же функциями, которые отдельно сверены со встроенным кодом EXE; настоящая GUI-генерация в установленном приложении и сеть компьютера преподавателя в этот сценарий не входили.

По присланному преподавателем скриншоту CUDA STT и обе речевые проверки RU/EN прошли. Это пользовательское свидетельство работоспособности на его текущей конфигурации, а не контролируемый замер скорости или потребления VRAM. Физические испытания разных GPU в этом выпуске не проводились; [требования к оборудованию](../HARDWARE_RU.md) и ограничения предыдущих измерений сохраняются.
